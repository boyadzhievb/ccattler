# M170 — Gate HTTPS Listener & End-to-End Validation

Move gate TLS termination from the service VIP to a node-level HTTPS listener
on the agent gate proxy, then validate it end to end on the deploy cluster.
Design: [design/gate-tls-termination.md § Node HTTPS Listener](../gate-tls-termination.md),
flow: [runtime-invariant-flows.md Flow 13](../runtime-invariant-flows.md).

## Why

M169 terminated TLS in the per-route cookie proxy, reached through a VIP:port
dispatch override. Planning this milestone found that design has structural
problems the unit tests did not catch:

| # | Problem in the M169 design | Evidence | Resolution in M170 |
|---|---|---|---|
| F1 | TLS-only gates (no `sticky`) are never dispatched to the TLS proxy on nftables. | `buildRouteDispatchOverrides` skips `StickyMethod == ""` (`network/nftables_dataplane.go:138`) | TLS leaves the VIP path entirely; branch removed. |
| F2 | iptables handles TLS-only gates but has no test. | `network/iptables_dataplane.go:124` | Branch removed with the rest of VIP TLS. |
| F3 | eBPF ignores gate TLS. | `network/ebpf_dataplane.go:484` | Userspace termination works on every data plane. |
| F4 | A TLS gate takes over the whole service VIP:port, breaking in-cluster plain-HTTP callers; two gates cannot share a service port. | override keyed by VIP:port | Service VIPs never carry gate TLS; SNI picks the gate. |
| F5 | Deploy-env external traffic goes through Caddy on testbed-100.43, bypassing gates. | `scripts/caddy-sync.sh` | E2E checks hit node `:443` directly from cluster nodes. Caddy integration out of scope. |

## Implementation

1. **Certificate map** in `UserSpaceProxy`: `host → *tls.Certificate`, refreshed with `routeHostMap` (5 s TTL); desired cert/key override derived. Unit tests: manual over auto precedence, refresh picks up rotation, removed gate drops its cert, malformed PEM skipped with a warning.
2. **HTTPS listener**: `--proxy-tls-listen` (default `--proxy-listen` host, port 443). `tls.Config{GetCertificate, MinVersion: TLS 1.2}`; unknown/missing SNI fails the handshake. Same `ServeHTTP` routing as `:80`. Host whose gate differs from the SNI's gate → 421.
3. **HTTP → HTTPS redirect** on the existing listener for hosts of TLS gates (308, path and query preserved).
4. **Cookie sticky over HTTPS**: extract `selectBackendFromCookie` / `buildStickyCookie` into shared helpers; gate proxy applies them for `sticky cookie` gates; cookie gets `Secure` on HTTPS.
5. **Remove VIP TLS**: `hasTLS` branches in nftables and iptables route chains, TLS in `CookieStickyProxy`, `TLSCertPEM`/`TLSKeyPEM` on `RouteDataPlaneConfig`, the agent's TLS reads in `agent/dataplane.go`, and their tests.
6. **Deploy**: Ansible worker template adds `--proxy-tls-listen {{ ansible_host }}:{{ proxy_tls_port | default(443) }}`; open 443 in any host firewall rules the roles manage.
7. **Docs**: `design/dsl-reference.md` TLS section — clients reach TLS gates on node `:443`; service ports stay plain HTTP.

## E2E Environment

- Deploy cluster on testbed-100.43 (vmherd): ctrl `192.168.124.10`, workers `.20` / `.30`; nftables data plane.
- Run via `test/e2e/cluster_test.sh --env deploy --workload gate-tls`.
- Cluster CA: `/etc/ccattler/ca.pem` on every node (`curl --cacert`).
- HTTPS checks from cluster nodes to `https://<host>` with `--resolve <host>:443:<node-ip>`, against every node.

## Test Workload

`test/e2e/workloads/gate-tls.cca` + `.workload`:

| Service (whoami, 2 instances) | Gate host | TLS | Sticky |
|---|---|---|---|
| `tls-auto` | `tls-auto.home.arpa` | `tls auto` | — |
| `tls-auto` | `tls-auto-alt.home.arpa` | `tls auto` | — (second gate, same service port) |
| `tls-manual` | `tls-manual.home.arpa` | `tls { cert key }` | — |
| `tls-sticky` | `tls-sticky.home.arpa` | `tls auto` | `cookie` |

The manual cert/key pair is generated by the test with `openssl` (self-signed, SAN = gate host) next to the `.cca` file before apply, never committed.

## Test Cases

| ID | Case | Pass criteria |
|----|------|---------------|
| T1 | Auto issuance | Within 60 s, `cca get gates` shows the three auto gates with EXPIRES ~90 days out, none `(pending)`. |
| T2 | HTTPS on every node | `curl --cacert ca.pem https://tls-auto.home.arpa` via each node's `:443` returns 200 + whoami body. |
| T3 | Certificate identity | `openssl s_client -servername` shows SAN = gate host, issuer = cluster CA; matches `cca describe gate`. |
| T4 | Manual cert served | Served fingerprint equals the generated cert. |
| T5 | Manual rotation | Regenerate cert, re-apply; new fingerprint within 30 s; zero failed requests in a 1 req/s loop. |
| T6 | Round-robin | 20 HTTPS requests to `tls-auto` reach both instances (whoami `Hostname`). |
| T7 | Sticky + TLS | First response sets a `Secure` sticky cookie; 10 requests with it hit one instance. |
| T8 | Two gates, one service port | `tls-auto` and `tls-auto-alt` each serve their own cert (by SNI) and both reach the service. |
| T9 | Service VIP untouched | Plain `http://` to the `tls-auto` service VIP:port from a node returns 200. |
| T10 | HTTP → HTTPS redirect | `http://tls-auto.home.arpa` on the plain proxy listener returns 308 to `https://`. |
| T11 | Unknown SNI / SNI–Host mismatch | Handshake for `unknown.home.arpa` fails; SNI `tls-auto` + Host `tls-manual` returns 421. |
| T12 | Cert stability | Restart `cca server` and one agent; fingerprint unchanged, traffic recovers. |
| T13 | Backend failure | Kill one `tls-auto` instance; HTTPS keeps succeeding within the health-check window. |
| T14 | TLS removal | Remove `tls` from `tls-manual`, re-apply; `:443` handshake for its host fails, `:80` serves it without redirect. |
| T15 | No key leakage | `cca get gates -o json`, `cca describe gate`, agent logs contain no `BEGIN`. |

Renewal-window logic stays covered by `controllers/route_tls_test.go`.
eBPF: the same workload runs on the bare-metal cluster (eBPF data plane) as a one-off check; not part of CI for M170.

## Phases

1. **Design** — this doc, `gate-tls-termination.md` revision, Flow 13 update. *(done)*
2. **Listener** — implementation steps 1–5 with unit tests; full `go test ./...` green.
3. **Workload + harness** — `gate-tls` workload, cert generation, T1–T15 in `cluster_test.sh`, each inside a retry/wait loop.
4. **Deploy + run** — Ansible change, run on the deploy cluster until green 3 consecutive times; one-off eBPF run on bare-metal.
5. **Ship** — `gate-tls` in the deploy-testbed workflow defaults, docs, release.

## Out of Scope

- Moving plain-HTTP cookie-sticky gates off the VIP (still uses the per-route cookie proxy).
- Caddy TLS passthrough on the testbed host, ACME, client-certificate auth on gates.

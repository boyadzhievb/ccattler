# Spec Delta

## ADDED Requirements

### Requirement: setup.sh installs the three CAs and each process's own certificates
The `setup.sh` generated by `cca init` SHALL install every CA and certificate `cca init` wrote under
`/etc/ccattler/pki` (certificates at 0644, keys at 0600, owned by root). It SHALL configure etcd to serve
`etcd-serving-certificate.pem` and trust only `etcd-access-ca.pem`. Each unit SHALL use its own process's
certificates (design.md D1a).

#### Scenario: Generated etcd trust and units
- **GIVEN** the `setup.sh` generated by `cca init`
- **WHEN** it is read
- **THEN** it sets up:
  - **etcd:** the TLS drop-in sets `ETCD_TRUSTED_CA_FILE=/etc/ccattler/pki/etcd-access-ca.pem` and
    `ETCD_CERT_FILE=/etc/ccattler/pki/etcd-serving-certificate.pem`;
  - **`cca-server`:** passes `--cert …/api-server-identity-certificate.pem`, `--ca …/cluster-identity-ca.pem`,
    `--gate-ca-cert …/gate-https-ca.pem`, `--etcd-cert …/cca-server-etcd-client-certificate.pem` and
    `--etcd-ca …/etcd-access-ca.pem`;
  - **`cca-agent`:** passes `--cert …/node-identity-for-api.pem`,
    `--etcd-cert …/node-etcd-client-certificate.pem` and `--etcd-ca …/etcd-access-ca.pem`;
  - **No old names:** no unit or drop-in names `ca.pem`, `node.pem` or `etcd.pem`.
- Test: `TestSetupScriptUsesEtcdCA`

#### Scenario: A fresh cluster works with three CAs
- **GIVEN** a fresh host set up with the guide (cca init and setup.sh)
- **WHEN** `cca-server` and `cca-agent` start and a service is applied
- **THEN** etcd is healthy over TLS, the node is alive and the service runs
- Check: `install-host:three-cas` (by hand on a fresh VM); the full Deploy Testbed run

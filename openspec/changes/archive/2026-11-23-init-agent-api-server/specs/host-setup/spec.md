# Spec Delta

## Purpose
States what `cca init` and the `setup.sh` it generates must install on a host, so a single-host cluster or the first control-plane node works like a node added with `cca join`.

## ADDED Requirements

### Requirement: The agent on a `cca init` host reaches its local API server
The agent service that `setup.sh` installs SHALL be configured with the address of the API server installed by the same script: the advertise address chosen at `cca init` and the API port 9770. It SHALL NOT depend on an address saved by `cca join`. With that address and the node certificate from `cca init`, secret delivery SHALL be enabled when the agent starts.

#### Scenario: Generated agent unit names the local API server
- **GIVEN** `cca init` run with advertise address `192.0.2.10`
- **WHEN** its `setup.sh` is generated
- **THEN** the `cca-agent` unit in the script passes `--api-server 192.0.2.10:9770`, and the `cca-server` unit in the same script listens on port 9770
- Test: `TestSetupScriptAgentUsesLocalAPIServer`

#### Scenario: The generated agent unit passes only flags the agent accepts
- **GIVEN** the `setup.sh` generated by `cca init`
- **WHEN** every flag of its `cca agent` command line is parsed by the agent's flag set
- **THEN** every flag, `--api-server` included, is accepted
- Test: `TestShippedUnitFilesPassOnlyKnownFlags`

#### Scenario: A service with a secret starts on a fresh `cca init` host
- **GIVEN** a fresh host set up only with `cca init` and its `setup.sh` (no `cca join`, no Ansible units)
- **WHEN** a configuration with a service that mounts a secret is applied
- **THEN** the agent log says `secret delivery from <advertise-address>:9770`, not `secret delivery not configured`; the instance reaches `running`; and the secret file is present inside the container
- Check: `install-host:secret-delivery` (by hand, on a fresh host)

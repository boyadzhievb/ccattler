Yes. I’d treat **v0.1 as a correctness release, not a feature release**.

The current prototype already has the right conceptual foundation—facts, desired/observed state, controllers, and a store abstraction. The main work is making those semantics *actually true under concurrency, failure, restarts, and missed events*. The current `StateStore` and runner are where I would focus first.

[CCattler repository](https://github.com/boyadzhievb/ccattler?utm_source=chatgpt.com)

# P0 — Do these before adding features

## 1. Redesign `StateStore`

Current:

```go
type StateStore interface {
    Get(...)
    Put(...)
    Delete(...)
    Scan(...)
    Watch(...)
    Transaction(...)
    Revision(...)
}
```

is close, but insufficient for a real reconciliation system.

Replace it conceptually with:

```go
type StateStore interface {
    Get(ctx context.Context, key string) (Fact, error)

    List(ctx context.Context, prefix string) (Snapshot, error)

    Put(ctx context.Context, key string, value []byte) (WriteResult, error)

    Delete(ctx context.Context, key string) (WriteResult, error)

    Txn(ctx context.Context, txn Transaction) (TxnResult, error)

    Watch(ctx context.Context, prefix string, opts WatchOptions) (Watch, error)

    Revision(ctx context.Context) (Revision, error)

    Close() error
}
```

Introduce:

```go
type Revision uint64

type Snapshot struct {
    Revision Revision
    Facts    []Fact
}

type WriteResult struct {
    Revision Revision
    Changed  bool
}

type TxnResult struct {
    Succeeded bool
    Revision  Revision
}

type WatchEvent struct {
    Revision Revision
    Type     EventType
    Fact     Fact
    Prev     *Fact
}

type Watch struct {
    Events <-chan WatchEvent
    Errors <-chan error
}
```

### Why

A controller needs to know:

> "I reconciled state at revision 183."

rather than merely:

> "I scanned some facts."

Your current `Scan()` gives no snapshot revision, so multiple scans can represent different states.

That becomes dangerous as soon as controllers operate concurrently.

---

# 2. Make revisions first-class

Every mutation must have exactly one monotonic revision.

More importantly:

**one transaction = one revision.**

Currently `MemoryStore.Transaction()` increments the global revision separately for each operation.

Change:

```text
transaction:
    PUT A
    PUT B
    DELETE C
```

from:

```text
revision 101 → A
revision 102 → B
revision 103 → C
```

to:

```text
revision 101:
    A changed
    B changed
    C deleted
```

All events generated by that transaction carry revision `101`.

This gives CCattler a coherent state model.

---

# 3. Make writes genuinely idempotent

This is one of the biggest fixes.

Currently:

```go
Put("foo", []byte("bar"))
Put("foo", []byte("bar"))
Put("foo", []byte("bar"))
```

creates three revisions/events even though nothing changed.

That can produce:

```text
controller
   ↓
PUT same value
   ↓
watch event
   ↓
controller
   ↓
PUT same value
   ↓
watch event
   ↓
...
```

Potential infinite reconciliation churn.

Implement:

```go
if existing != nil && bytes.Equal(existing.Value, value) {
    return WriteResult{
        Revision: existing.Revision,
        Changed:  false,
    }, nil
}
```

No revision.

No event.

No reconciliation trigger.

**This should be a store invariant.**

---

# 4. Fix watch semantics

The current watcher silently drops events when its 64-entry buffer fills.

That is unacceptable for the control plane.

But don't make the watcher blocking either.

Instead:

### Watch events are notifications, not the source of truth.

The invariant should be:

> Missing an event must never cause the cluster to remain permanently incorrect.

Implement revision-aware watches:

```text
Watch(prefix, startRevision)
```

If the watcher falls behind:

```text
WATCH_GAP
     ↓
controller resync
     ↓
List(prefix)
     ↓
reconcile
```

Even better:

```go
type WatchError struct {
    Code       WatchErrorCode
    Revision   Revision
}
```

with:

```go
ErrCompacted
ErrWatchOverflow
ErrStoreClosed
```

The controller then does:

```text
event
  ↓
reconcile

watch gap
  ↓
full resync
  ↓
reconcile
```

This is much more important than trying to build a "perfect" event delivery mechanism.

---

# 5. Make `Watch(ctx)` lifecycle-safe

Current `Watch()` registers a watcher but doesn't unregister it when the context is cancelled. It also allows operations after `Close()`.

Fix all of these.

Required invariants:

```text
Close()
 ├─ prevents new operations
 ├─ terminates watches
 └─ releases all resources
```

Every store method must return:

```go
ErrStoreClosed
```

after close.

And:

```go
Watch(ctx)
```

must remove its watcher when:

```go
ctx.Done()
```

fires.

Test:

```text
1000 watches
cancel all
assert watcher count == 0
```

---

# 6. Deep-copy fact values

Current `Get()` and `Scan()` copy the `Fact` struct but not the underlying `[]byte`. The comments claim defensive copies, but the bytes remain shared.

Fix:

```go
func cloneBytes(v []byte) []byte {
    if v == nil {
        return nil
    }

    out := make([]byte, len(v))
    copy(out, v)
    return out
}
```

Then clone:

```go
Fact.Value
Event.Fact.Value
Event.Prev.Value
Op.Value
```

every time data crosses the store boundary.

---

# 7. Add an atomic reconciliation commit

Current runner behavior is:

```text
Reconcile()
   ↓
Put()
Put()
Put()
Delete()
```

sequentially.

Change the controller contract to return a transaction:

```go
type ReconcileResult struct {
    Changes []Change
    Preconditions []Compare
}
```

or preferably:

```go
type ReconcilePlan struct {
    BaseRevision Revision
    Preconditions []Compare
    Changes       []Change
}
```

Then:

```text
snapshot @ revision 200
        ↓
controller computes plan
        ↓
transaction:
    compare revision == 200
    apply all changes
        ↓
success
```

If another controller changed relevant state:

```text
compare fails
     ↓
discard plan
     ↓
re-read
     ↓
reconcile again
```

That is the foundation of deterministic concurrent controllers.

---

# 8. Redesign the Controller interface

Current:

```go
type Controller interface {
    Name() string
    Watch() []string
    Reconcile(ctx context.Context, facts []store.Fact) ([]Change, error)
}
```

I would change it to:

```go
type Controller interface {
    Name() string

    Dependencies() []Dependency

    Reconcile(
        ctx context.Context,
        snapshot Snapshot,
    ) (Plan, error)
}
```

Where:

```go
type Dependency struct {
    Prefix string
    Mode   DependencyMode
}

type DependencyMode int

const (
    DependencyRead DependencyMode = iota
    DependencyWatch
)
```

This separates:

```text
what I need to read
```

from:

```text
what wakes me up
```

That becomes extremely useful later.

---

# 9. Give every controller a clear input/output domain

Don't allow arbitrary controllers to scan the whole store.

For example:

### Scheduler

Reads:

```text
desired/services
desired/instances
observed/nodes
policies/placement
quotas
```

Writes:

```text
placement/instances
```

### Endpoint controller

Reads:

```text
desired/services
observed/instances
```

Writes:

```text
desired/endpoints
```

### Autoscaler

Reads:

```text
desired/services
observed/instances
observed/metrics
policies/scaling
quotas
```

Writes:

```text
desired/services/{service}/instances
```

Document this as a controller contract.

---

# 10. Prevent controller write conflicts

Every controller should have an explicit write domain:

```go
type ControllerSpec struct {
    Name       string
    Reads      []Prefix
    Watches    []Prefix
    Writes     []Prefix
}
```

At startup validate:

```text
scheduler writes /placement
endpoint writes /endpoints
autoscaler writes /desired/service/*/instances
```

and reject two controllers that own the same authoritative keyspace.

This prevents accidental "two controllers fighting over the same fact."

# P1 — Fix the runner

## 11. Replace current `Runner.Run()`

Current runner returns as soon as *any* controller exits and doesn't cancel/wait for the others.

Use a child context:

```text
Runner.Run(ctx)
       │
       ├── controller A
       ├── controller B
       ├── controller C
       └── controller D
```

If one fails:

```text
controller B fails
       ↓
cancel child context
       ↓
stop A/C/D
       ↓
wait for all
       ↓
return B error
```

Use `errgroup.WithContext`.

Conceptually:

```go
func (r *Runner) Run(ctx context.Context) error {
    ctx, cancel := context.WithCancel(ctx)
    defer cancel()

    g, ctx := errgroup.WithContext(ctx)

    for _, controller := range r.controllers {
        controller := controller

        g.Go(func() error {
            return r.runController(ctx, controller)
        })
    }

    return g.Wait()
}
```

# 12. Add controller restart/backoff

Don't immediately spin a broken controller.

Use:

```text
failure
 ↓
100ms
 ↓
500ms
 ↓
1s
 ↓
2s
 ↓
5s
 ↓
30s max
```

But distinguish:

### Fatal

```text
invalid controller configuration
corrupt state schema
permission denied permanently
```

from:

### Transient

```text
store unavailable
network temporarily unavailable
runtime temporarily unavailable
```

Controllers should expose health state:

```text
controller/scheduler/status
controller/network/status
```

---

# 13. Add periodic resync

Even with watches:

```text
watch + periodic resync
```

is much safer.

For v0.1:

```text
watch events → immediate reconcile
every 30s → full resync
```

This catches:

* dropped notifications
* bugs in watch filtering
* stale controller state
* missed startup events
* future backend inconsistencies

The periodic resync is a **correctness backstop**, not the primary mechanism.

---

# 14. Stop generating semantic events inside the runner

This code is a smell:

```go
classifyChangeAsEvent(change)
```

because the runner infers semantic meaning from key strings.

Instead:

```text
state mutation
      ↓
store event
      ↓
event projection
```

Create a separate:

```go
EventProjector
```

that observes actual committed store events.

Then:

```text
controller proposes change
        ↓
transaction commits
        ↓
store emits committed event
        ↓
event projector interprets it
```

That means failed transactions cannot produce fake events.

# P1 — Separate desired, observed, and derived state

## 15. Make the distinction structural

Use explicit key domains:

```text
/ccattler/
    desired/
    observed/
    derived/
    policy/
    placement/
```

I would make this a hard architectural rule.

### Desired

What the system should be.

### Observed

What the system reports is happening.

### Derived

Facts computed from other facts.

### Policy

Constraints/rules governing decisions.

### Placement

A scheduler decision.

This is much cleaner than letting controllers invent arbitrary fact categories.

---

# 16. Introduce "effective state"

You already have the concept in the codebase.

Formalize it:

```text
desired
   +
policy
   +
quota
   +
capacity
   +
placement
   ↓
effective
```

For example:

```text
desired instances = 20
tenant quota       = 10
cluster capacity   = 8

effective instances = 8
```

The user should be able to ask:

```text
desired:   20
effective:  8
reason:    cluster_capacity
```

This is one of CCattler's strongest potential UX advantages.

# P1 — Refactor the agent

This is the other major architectural change.

The current agent is doing:

```text
node registration
heartbeat
runtime
network
storage
secrets
health checks
configuration
cleanup
```

That is too much for one component.

Break it into:

```text
agent/
    agent.go

    node/
        reporter.go

    runtime/
        reconciler.go

    network/
        reconciler.go

    storage/
        reconciler.go

    secrets/
        materializer.go

    health/
        reporter.go
```

The top-level agent should mostly orchestrate these.

---

# 17. Make the agent observe runtime reality

This is critical.

Don't do:

```text
runtime.Start()
     ↓
publish Running
```

Instead:

```text
runtime.Start()
     ↓
runtime.Status()
     ↓
actual process/container state
     ↓
publish observation
```

The runtime is authoritative about runtime reality.

So:

```go
Start() error
Status() RuntimeStatus
List() []RuntimeInstance
Stop() error
```

Then the agent reports:

```text
observed/instance/{id}/state
observed/instance/{id}/exit_code
observed/instance/{id}/started_at
observed/instance/{id}/runtime_id
```

---

# 18. Remove `127.0.0.1` as a semantic fallback

This:

```text
no IP → 127.0.0.1
```

is dangerous.

An absent IP should mean:

```text
NetworkUnavailable
```

not:

```text
localhost
```

Otherwise networking failures can masquerade as valid connectivity.

---

# 19. Make cleanup transactional at the lifecycle level

Instance lifecycle should look like:

```text
ALLOCATE
   ↓
PREPARE
   ↓
START
   ↓
OBSERVE
   ↓
HEALTHY
```

Failure:

```text
ALLOCATE
   ↓
PREPARE
   ↓
START FAILED
   ↓
CLEANUP
   ↓
FAILED observation
```

The current agent has failure paths where secrets/network allocations can survive a failed start.

Give every runtime instance a resource ownership record:

```text
/observed/instance/{id}/resources
```

containing:

```text
runtime_id
network_allocation
volume_attachments
secret_materializations
```

Then cleanup becomes deterministic after agent restart.

---

# 20. Add leases for node liveness

You already have:

```go
LeaseID int64
```

but the memory implementation doesn't actually implement lease semantics.

For v0.1:

```text
node registers
     ↓
lease acquired
     ↓
heartbeat renews lease
     ↓
lease expires
     ↓
node becomes unavailable
```

Do **not** write heartbeat facts every second forever.

That produces revision churn.

Separate:

```text
node identity
node capabilities
node state
node heartbeat/lease
```

# P1 — Fix health checking

The DSL supports:

```text
every 10s
```

but the agent reconciliation loop currently runs approximately every second, and health handling is coupled to that loop.

Implement an explicit health scheduler:

```text
health policy
     ↓
next check timestamp
     ↓
probe
     ↓
observed health fact
```

Example:

```text
/observed/instance/web-1/health
    status = healthy
    checked_at = ...
```

The runtime reconciler shouldn't care whether health checks happen every 1s or 30s.

# P2 — Make keys a real type

Today keys are raw strings everywhere.

Introduce:

```go
type Key struct {
    Domain string
    Scope  string
    Kind   string
    ID     string
    Field  string
}
```

with canonical encoding:

```text
/ccattler/observed/instance/abc/state
```

but don't expose string concatenation throughout the codebase.

Instead:

```go
keys.ObservedInstanceState(id)
```

and:

```go
keys.ObservedInstances()
```

This eliminates a huge class of bugs from:

```go
strings.TrimPrefix(...)
strings.TrimSuffix(...)
strings.Split(...)
```

The endpoint controller is already doing this kind of path manipulation, including assumptions around exposed ports. That should disappear behind typed key helpers.

---

# P2 — Introduce typed fact codecs

Don't make controllers repeatedly do:

```go
string(fact.Value)
json.Unmarshal(...)
strings.Split(...)
```

Introduce:

```go
type Codec[T any] interface {
    Encode(T) ([]byte, error)
    Decode([]byte) (T, error)
}
```

Then:

```go
InstanceDesired
InstanceObserved
ServiceDesired
NodeObserved
Placement
NetworkEndpoint
```

become typed internal representations.

The **user ontology remains declarative/fact-oriented**; this is purely an implementation safety mechanism.

# P2 — Formalize controller determinism

Every controller should satisfy:

```text
same snapshot
    +
same policies
    ↓
same plan
```

Add tests such as:

```go
plan1 := controller.Reconcile(snapshot)
plan2 := controller.Reconcile(snapshot)

require.Equal(plan1, plan2)
```

Then:

```text
apply(plan)
apply(plan)
```

must converge to the same state.

This should become a first-class package:

```text
sim/

    runtime.go

    metrics.go
```

Then test:



# P3 — Security architecture

Don't try to finish all production security in v0.1.

But establish the interfaces now:

```go
type Authorizer interface {
    Authorize(
        ctx context.Context,
        principal Principal,
        action Action,
        resource Resource,

```

and:

```go
type IdentityProvider interface {
    Authenticate(...)
```

Controllers receive identities rather than directly manipulating auth mechanisms.

# P3 — Networking abstraction

Keep your existing high-level direction.

# The v0.1 state machine

I would make this the canonical CCattler lifecycle:

```text
                    ┌──────────────┐
                    │    INTENT    │
                    └──────┬───────┘
                           ↓
                    ┌──────────────┐
                    │   DESIRED    │
                    └──────┬───────┘
                           ↓
                    ┌──────────────┐
                    │    POLICY    │
                    └──────┬───────┘
                           ↓
                    ┌──────────────┐
                    │   EFFECTIVE  │
                    └──────┬───────┘
                           ↓
                    ┌──────────────┐
                    │  PLACEMENT   │
                    └──────┬───────┘
                           ↓
                    ┌──────────────┐
                    │ RECONCILIATION│
                    └──────┬───────┘
                           ↓
                    ┌──────────────┐
                    │    REALITY   │
                    └──────┬───────┘
                           ↓
                    ┌──────────────┐
                    │  OBSERVATION │
                    └──────┬───────┘
                           │
                           └──────────────► DESIRED
```

And the **single most important invariant**:

> **Controllers produce plans. The store commits state. Agents produce observations. Nothing treats an action as truth.**

# What I would explicitly NOT build for v0.1

Don't let these distract from the architecture:

* distributed etcd implementation
* multi-region clusters
* sophisticated autoscaling algorithms
* CRDs
* YAML compatibility
* Kubernetes API compatibility
* service mesh
* GPU scheduling
* sophisticated CNI integration
* cloud-specific infrastructure
* HA control plane
* fancy UI

Instead, v0.1 should prove one thing:

> **CCattler can take declarative intent, derive state, reconcile it against reality, survive missed events/controller restarts/node failures, and deterministically converge.**

If you can demonstrate:

```text
CCattler config
      ↓
facts
      ↓
desired state
      ↓
scheduler
      ↓
placement
      ↓
agent
      ↓
real container
      ↓
observation
      ↓
controller detects failure
      ↓
replacement
      ↓
healthy cluster
```

**after killing the node agent, restarting the controller, dropping watch events, and changing desired state concurrently**, then I would consider CCattler v0.1 architecturally real.

The current code is already surprisingly close conceptually; the biggest mistake now would be adding more controllers/features before fixing the **revision + transaction + watch + reconciliation semantics**.
